### 4.4 请求 / 应答回路（PING）

`keel-host --plugins <dir> --once` 启动 hello 后：

```text
started hello (plugin_id=1)
ping hello ok
```

这条链路验证了：Host 按 plugin_id 投递 COMMAND → 插件 Worker 分发 → 插件回 COMPLETE →
Host 按 correlation 命中。当前只在启动后体检时走一次。

带 `--serve-ms=400` 时：

```text
ping hello ok
Keel 在 75ms 内完成启动
serve finished
shutdown
stopped 1 plugin(s)
```

### 4.5 调度器（延时 / 周期 / 取消）

`hello` 在 `onEnable` 注册一个 30ms 延时任务，以及一个 20ms 起、50ms 周期的任务；
周期任务第 3 次自行取消。`--serve-ms=400` 输出：

```text
调度器自检：延时 30ms 任务
调度器自检：周期任务第 1 次
调度器自检：周期任务第 2 次
调度器自检：周期任务第 3 次
```

没有第 4 次，说明 `TaskHandle.cancel()` 生效。

### 4.6 HTTP 冒烟（Host 自带 Ktor）

```powershell
keel-host --plugins <dir> --http=7180 --serve-ms=8000
curl.exe http://127.0.0.1:7180/healthz
curl.exe http://127.0.0.1:7180/ping
```

```text
/healthz HTTP:200  → ok
/ping    HTTP:200  → ok
```

`/ping` 走的是完整链路：Ktor handler 挂起 → 泵线程投 COMMAND 给 hello → 插件回 COMPLETE →
泵线程 resume → HTTP 200（§4.6 的日志里能看到 `ping hello ok` 与 serve 周期）。

日志：

```text
[INFO] (io.ktor.server.Application): Application started in 0.001 seconds.
http listening on 0.0.0.0:7180
Keel 在 80ms 内完成启动
serve finished
shutdown
```

`--http` 使用 Ktor CIO，验证了 mingwX64 上可以正常起服务与关闭；插件业务路由见 §4.7。

### 4.7 插件路由冒烟

hello 在 `onLoad` 里手工注册 `GET /hello`（KSP 未接）：

```powershell
keel-host --plugins <dir> --http=7183 --serve-ms=12000
curl.exe http://127.0.0.1:7183/hello
```


```text

started hello (plugin_id=1)
```

说明注册事件在启动等待期就被消费，HTTP 开始服务时路由表已就绪。

### 4.10 单 exe 冒烟（mingwX64，2026-11-12）

`keel-plugin-hello` 临时 `executable { enabled = true; name = "hello-app" }` 后
`gradlew -p keel-plugin-hello keelExecutableMingwX64`：

```text
hello-app.exe  25.4 MB（含 hello 的 .keel；PE 里能找到 KEELBUNDLE / IDR_KEEL_BUNDLE）
bundle: <exe>（1 个内嵌包，被磁盘覆盖 0 个）
source: embedded://plugins/hello!/lib/mingwX64/keel_plugin_hello.dll
resources: [hello.txt, web/index.html]
plugins: $KEEL_HOME/plugins    cache: $KEEL_HOME/.cache
ping hello ok   failed: 0   http listening on 0.0.0.0:7191
```

运行目录只有 `plugins/`（空）与 `.cache/hello/0.1.0/1/`（资源物化 + dll），没有 `.keel` 解压产物；
把 `.keel` 放进 `plugins/` 后重启：`被磁盘覆盖 1 个`，source 变为磁盘路径。
`--plugins <dir> --once` 旧模式回归正常。

已知限制：`gradlew -p keel-host build` / hello 的 `build` 在 Windows 上会在 `linuxArm64`
链接阶段报 `build/generated/keel-abi/linuxArm64/lib/linuxArm64` 不存在——`keel-abi` 的
`abiTargets` 默认只编宿主目标，zip 里没有 linux 静态库；只在 mingw 任务上验证。
